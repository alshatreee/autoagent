# VPS Deployment — Polymarket Bots (arb1/arb2/arb3)

Full setup from a fresh **Ubuntu 22.04** DigitalOcean droplet to three running bots.

## Architecture

```
/root/bots/
├── copy_trader.py            arb1 — copies a single smart wallet
├── oracle_arb_wss.py         arb2 — Chainlink↔Polymarket arbitrage
├── sports_trader_finder.py   tool — generates smart_wallets.json
├── sports_consensus_bot.py   arb3 — sports consensus with SL/TP/time exit
├── telegram_notify.py        shared notifier
├── watchdog.sh               restarts dead screen sessions
├── .env                      secrets (chmod 600, never commit)
├── smart_wallets.json        generated by sports_trader_finder.py
├── logs/                     systemd log files
└── *_state.json              persistent bot state
```

Two process management options are provided:
1. **systemd** (recommended) — automatic restart, log rotation, hardening
2. **screen + watchdog cron** (their original setup, still supported)

## 4. Configure secrets

```bash
cp /root/bots/.env.template /root/bots/.env
nano /root/bots/.env
chmod 600 /root/bots/.env
```

Required values:

| Variable | How to get it |
|---|---|
| `POLY_PRIVATE_KEY` | Your wallet's private key (LIVE only — leave blank for paper) |
| `POLY_FUNDER` | Same as wallet address for EOA, or proxy address |
| `POLY_SIG_TYPE` | `0` for EOA wallets (your case based on the audit) |
| `TARGET_WALLET` | sharky6999's full address |
| `ALCHEMY_WSS` | Free key from https://dashboard.alchemy.com/ |
| `TELEGRAM_BOT_TOKEN` | `/newbot` to @BotFather on Telegram |
| `TELEGRAM_CHAT_ID` | Message @userinfobot on Telegram |

Test telegram:

```bash
set -a; . /root/bots/.env; set +a
python3 /root/bots/telegram_notify.py
# expected: "sent"
```

## 6. Configure arb2 markets (oracle arb)

`oracle_arb_wss.py` ships with an EMPTY `MARKETS` list. The bot refuses to start until you fill it:

```bash
nano /root/bots/oracle_arb_wss.py
```

Find `MARKETS = [` and add real Polymarket slugs:

```python
MARKETS = [
    {
        "slug":     "will-bitcoin-hit-100k-by-end-of-2026",
        "asset":    "BTC",
        "strike":   100_000,
        "side":     "above",
        "deadline": "2026-12-31T23:59:59Z",
    },
    # add more
]
```

Find slugs by browsing https://polymarket.com — the slug is the URL after `/event/`.

## 7. Run bots — Option A: systemd (recommended)

Install service files:

```bash
cp /root/bots/polybot-arb1.service /etc/systemd/system/
cp /root/bots/polybot-arb2.service /etc/systemd/system/
cp /root/bots/polybot-arb3.service /etc/systemd/system/
systemctl daemon-reload
```

Enable + start:

```bash
systemctl enable polybot-arb1 polybot-arb2 polybot-arb3
systemctl start  polybot-arb1 polybot-arb2 polybot-arb3
```

Status check:

```bash
systemctl status polybot-arb1 --no-pager
systemctl status polybot-arb2 --no-pager
systemctl status polybot-arb3 --no-pager
```

Live logs:

```bash
journalctl -u polybot-arb1 -f
# or:
tail -f /root/bots/logs/arb1.log
```

Stop a bot:

```bash
systemctl stop polybot-arb1
```

## 7. Run bots — Option B: screen + watchdog (original setup)

If you prefer the original architecture:

```bash
# Manual start once
screen -dmS arb1 bash -c "set -a; . /root/bots/.env; set +a; cd /root/bots && python3 copy_trader.py --paper"
screen -dmS arb2 bash -c "set -a; . /root/bots/.env; set +a; cd /root/bots && python3 oracle_arb_wss.py --paper"
screen -dmS arb3 bash -c "set -a; . /root/bots/.env; set +a; cd /root/bots && python3 sports_consensus_bot.py --paper"

# Watchdog cron (revives dead sessions every minute)
crontab -e
# add:
* * * * * /root/bots/watchdog.sh >> /root/bots/logs/watchdog.log 2>&1
@reboot   /root/bots/watchdog.sh >> /root/bots/logs/watchdog.log 2>&1
```

Attach to a session:

```bash
screen -r arb1     # Ctrl+A then D to detach
```

Stop a bot manually:

```bash
screen -X -S arb1 quit
# protect a stopped paper bot from accidental watchdog restart by removing
# its entry from watchdog.sh SESSIONS array
```

## 8. Going LIVE (after 1+ month of paper)

1. **Audit paper logs** — verify the bots are profitable on paper before risking real money
2. **Fund the wallet** — send USDC.e on Polygon to your `POLY_FUNDER`
3. **Verify wallet** — `python3 -c "from eth_account import Account; print(Account.from_key(open('/root/bots/.env').read().split('POLY_PRIVATE_KEY=')[1].split()[0]).address)"` should match `POLY_FUNDER` for EOA wallets
4. **Edit each bot** to remove `--paper` flag in:
   - `polybot-arb1.service` ExecStart line
   - `polybot-arb2.service` ExecStart line
   - `polybot-arb3.service` ExecStart line
   - or `watchdog.sh` SESSIONS array if using screen
5. **Reload + restart**:
   ```bash
   systemctl daemon-reload
   systemctl restart polybot-arb1 polybot-arb2 polybot-arb3
   ```
6. **Watch the first hour like a hawk** — `journalctl -f -u polybot-arb*`

```bash
# Are all bots up?
systemctl is-active polybot-arb1 polybot-arb2 polybot-arb3

```

### Wallet balance check

```bash
python3 - <<'EOF'
import os
from web3 import Web3
w3 = Web3(Web3.HTTPProvider(os.getenv("ALCHEMY_HTTP",
    "https://polygon-rpc.com")))
addr = os.getenv("POLY_FUNDER")
USDC_E = "0x2791Bca1f2de4661ED88A30C99A7a9449Aa84174"
abi = [{"constant":True,"inputs":[{"name":"_owner","type":"address"}],
        "name":"balanceOf","outputs":[{"name":"","type":"uint256"}],
        "type":"function"}]
c = w3.eth.contract(address=Web3.to_checksum_address(USDC_E), abi=abi)
bal = c.functions.balanceOf(Web3.to_checksum_address(addr)).call() / 1e6
print(f"USDC.e balance: ${bal:.2f}")
EOF
```

## 11. Common issues

| Symptom | Likely cause | Fix |
|---|---|---|
| `403 Trading restricted` | Wallet flagged by Polymarket | New wallet (same as before) |
| `not_enough_balance` | USDC.e not in proxy wallet | Fund POLY_FUNDER on Polygon |
| `invalid signature` | `POLY_SIG_TYPE` wrong | Try 0/1/2; for your EOA wallets it's `0` |
| `[wallets] file not found` | sports_trader_finder not run | Run it once before starting arb3 |
| `MARKETS is empty` (arb2) | Skipped market config | Edit `oracle_arb_wss.py` MARKETS list |
| Bot exits immediately | Preflight failed | Check `journalctl -u polybot-arbN -n 50` |
| watchdog spamming "FAILED to start" | Bot crashes on startup | Run the command manually to see real error |

## 12. Safety checklist before going live

```
[ ] Paper traded for >= 30 days with positive PnL on each bot
[ ] Verified POLY_FUNDER matches your funded wallet on polymarket.com
[ ] Wallet has at least $200 USDC.e (covers ~10 trades on each bot)
[ ] sports_trader_finder.py output reviewed manually — addresses make sense
[ ] arb2 MARKETS list contains markets you've sanity-checked manually
[ ] Telegram receives test notification successfully
[ ] systemd services start cleanly: systemctl status all green
[ ] /root/bots/.env has chmod 600
[ ] Daily loss limits set conservatively (you can afford to lose them)
[ ] You have a kill plan: `systemctl stop polybot-arb*` is muscle memory
```

## 13. Maintenance

### Weekly
- Re-run `sports_trader_finder.py` (cron does this Mondays at 04:00 UTC)
- Check telegram for any error pings

### Monthly
- Audit each bot's PnL — kill any that's lost money
- Top up USDC.e if needed
- Update dependencies: `pip3 install --upgrade aiohttp py-clob-client web3`

### After any code edit
```bash
chattr -i /root/bots/<file>

chattr +i /root/bots/<file>
systemctl restart polybot-<bot>
```

## 14. Emergency stop

```bash
# Stop everything immediately
systemctl stop polybot-arb1 polybot-arb2 polybot-arb3

# Or with screen
for s in arb1 arb2 arb3; do screen -X -S $s quit; done

# Disable auto-restart until you fix the issue
systemctl disable polybot-arb1 polybot-arb2 polybot-arb3
```

Your open positions will NOT auto-close — log into polymarket.com and close them manually if needed.
